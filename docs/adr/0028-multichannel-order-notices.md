# ADR 0028 — إشعارات الطلبات على القنوات الخارجية

الحالة: مقبول (الخطوة 42د)

## القرار
1. **الإشعار الداخلي زي ما هو.** `notifyPortalCustomer` بيكتب صف الإشعار في البوابة الأول (ده المصدر الأساسي)، وبعدها بيطلب نسخة خارجية.
2. **أنواع محددة بس** (`src/lib/portalNoticeCore.ts`): تسعير، رفض، إلغاء صنف، رد على سؤال سعر، بدء الإنتاج، جاهز للتسليم، تسليم، إلغاء. رسائل المحادثة وطلبات استعادة كلمة السر وفحوصات الجودة الداخلية تفضل جوه البوابة (كتيرة أو داخلية).
3. **المستلمون:** الموظف صاحب الطلب + أصحاب الشركة، بدون تكرار.
4. **القنوات:** إعداد `delivery.notice.channels` (عام أو لكل شركة، الموظف يعدّله). الافتراضي إيميل وتيليجرام، والإرسال بس للقنوات اللي المستخدم أكّدها بنفسه (نفس سياسة التنبيهات الأمنية). فاضي = جوه البوابة بس. الرسايل النصية خارج القايمة لحد ما تتوفر خدمة مجانية.
5. **مضمون ومش مكرر:** حدث `portal.notice` في صندوق الصادر، واحد لكل مستلم (فشل واحد ما يكرّر للباقي)، بمفتاح منع تكرار بالساعة. بنحاول فورًا بحد أقصى ثانيتين، والباقي يكمّله العامل بتراجع زمني.
6. **ما بيكسّرش العملية:** أي خطأ في الطابور بيتسجّل تحذير والإشعار الداخلي يفضل سليم.
7. **الخصوصية:** نص الرسالة مش بيتخزن في سجل الإرسال، والوجهة بتتخزن مقنّعة (نفس `deliver`).
8. **القالب:** `order_notice` (الموضوع = عنوان الإشعار)، وممكن الموظف يعدّل صياغته من `copy.overrides` بالمفتاحين `msg.order_notice.subject/body`.
