# دليل النسخ الاحتياطي والاسترجاع

## كيف يعمل

- **كل يوم 03:30 بتوقيت القاهرة** يشتغل workflow اسمه `backup` على GitHub Actions: ياخد نسخة كاملة من قاعدة Neon (`pg_dump`)، يشفّرها بأداة `age` بالمفتاح العام، ويرفعها لكل مخزن مضبوط (Cloudflare R2، وBackblaze B2 لما يتفعّل). مفيش أي نسخة بتتخزّن غير مشفّرة.
- **كل أحد** يشتغل `restore-test`: ينزّل آخر نسخة من كل مخزن، يتأكد إن الملف ما اتغيّرش (sha256 وحجم)، يفك التشفير، يسترجعها في قاعدة Postgres مؤقتة، ويقارن عدد الصفوف في كل جدول بالعدد المسجّل وقت النسخ. أي فرق = فشل.
- **صفحة «صحة النظام» ← «النسخ الاحتياطي واختبار الاسترجاع»** بتقول بالعربي: آخر نسخة من كام ساعة، في أي مخزن، حجمها، وآخر اختبار استرجاع. أصفر لو النسخة اتأخرت 36 ساعة أو الاختبار 10 أيام، وأحمر لو 72 ساعة أو 21 يوم أو أي فشل.
- **الاحتفاظ:** كل نسخ آخر 14 يوم، ونسخة كل أحد لمدة 8 أسابيع، ونسخة أول كل شهر لمدة 12 شهر، وآخر 3 نسخ دايمًا. مفيش مسح بيحصل لو هيمسح أكتر من نص النسخ مرة واحدة.
- لو أي مخزن فشل، الـworkflow بيفشل وGitHub بيبعتلك إيميل، وفحص الصحة بيبقى أحمر.

## التفعيل (مرة واحدة)

### 1) هجرة قاعدة البيانات

نفس طريقة الخطوات السابقة: `npm run db:migrate` (بتطبّق 0084 وتنشئ جدول `backup_runs`).

### 2) مفتاح التشفير (على جهازك، مش في الشات)

1. نزّل أداة age لويندوز من صفحة الإصدارات: https://github.com/FiloSottile/age/releases (الملف اسمه شبه `age-v1.x.x-windows-amd64.zip`).
2. فُكّه وشغّل في PowerShell:
   ```powershell
   Expand-Archive "E:\age-v1.x.x-windows-amd64.zip" "E:\age"
   & "E:\age\age\age-keygen.exe" -o "E:\hypertech-backup-key.txt"
   ```
   هيطبع سطر `Public key: age1...`. الملف `hypertech-backup-key.txt` فيه المفتاح الخاص.
3. **احفظ نسخة من الملف ده في مكانين برّه المشروع** (فلاشة + مدير كلمات سر). **لو ضاع، كل النسخ مش هتتفتح أبدًا.**

### 3) أسرار GitHub

من المستودع: Settings ← Secrets and variables ← Actions ← New repository secret. أضف:

| الاسم                                                                     | القيمة                                                                                                             |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `BACKUP_DATABASE_URL`                                                     | رابط Neon **المباشر** (من لوحة Neon: Connect، وألغِ تفعيل Connection pooling). الرابط بدون `-pooler` في اسم المضيف |
| `BACKUP_AGE_PUBLIC_KEY`                                                   | السطر `age1...` (المفتاح العام)                                                                                    |
| `BACKUP_AGE_PRIVATE_KEY`                                                  | كل محتوى `hypertech-backup-key.txt` (يستخدمه `restore-test` فقط)                                                   |
| `R2_ENDPOINT`                                                             | `https://<account-id>.r2.cloudflarestorage.com`                                                                    |
| `R2_BUCKET`                                                               | `hyper-tech-backup-a`                                                                                              |
| `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY`                               | من توكن R2                                                                                                         |
| `B2_ENDPOINT` / `B2_BUCKET` / `B2_ACCESS_KEY_ID` / `B2_SECRET_ACCESS_KEY` | من Backblaze (اختياري لحد ما يتفعّل؛ لو ناقص بيتجاهل بتحذير)                                                       |

### 4) أول تشغيل

Actions ← `backup` ← Run workflow. لما ينجح، شغّل `restore-test` بنفس الطريقة وافتح ملخص التشغيلة: جدول بعدد الجداول والصفوف. بعدها افتح «صحة النظام» وتأكد إن كارت النسخ أخضر.

## استرجاع بعد عطل حقيقي

1. اعمل مشروع/قاعدة Neon جديدة فاضية، وانسخ رابطها المباشر.
2. من لوحة R2 (أو Backblaze) نزّل أحدث ملف `daily/hypertech-<التاريخ>.dump.age` وملف الـ`manifest.json` اللي بنفس الاسم.
3. فك التشفير (يحتاج `age` و`hypertech-backup-key.txt`):
   ```powershell
   & "E:\age\age\age.exe" -d -i "E:\hypertech-backup-key.txt" -o "E:\restore\db.dump" "E:\restore\hypertech-<التاريخ>.dump.age"
   ```
4. استرجع (يحتاج أدوات عميل PostgreSQL 17 على الجهاز):
   ```powershell
   pg_restore --no-owner --no-privileges --dbname="<رابط Neon الجديد>" "E:\restore\db.dump"
   ```
5. قارن عدد الصفوف بـ`countsAfter` في الـmanifest، وغيّر `DATABASE_URL` في Vercel للقاعدة الجديدة وأعد النشر.

## ملاحظات وحدود معروفة

- **التشفير غير متماثل:** النسخ بتتشفّر بالمفتاح العام فقط، فسرقة أسرار وظيفة النسخ ما تفتحش النسخ القديمة. لكن المفتاح الخاص موجود كسر في GitHub لاختبار الاسترجاع، فاختراق حساب GitHub نفسه + المخزن مع بعض يكشف النسخ. لو عايز فصل أقوى، شيل `BACKUP_AGE_PRIVATE_KEY` من GitHub وشغّل اختبار الاسترجاع يدويًا بالمفتاح من جهازك.
- **ما بتنسخش:** ملفات Vercel (الكود في GitHub) ومتغيرات البيئة (احتفظ بنسخة منها في مدير كلمات السر). الصور المرفوعة لو بتتخزن برّه قاعدة البيانات مش جزء من النسخة.
- **إصدار Postgres:** الأدوات على 17 (`PG_MAJOR` في الـworkflows). لو Neon رقّى لإصدار 18، `pg_dump` هيرفض بخطأ واضح «server version mismatch»، وغيّر الرقم في الملفين وفي `action.yml`.
- **لو GitHub وقف الـcron:** بيحصل في المستودعات العامة بعد 60 يوم من عدم النشاط. مستودعنا خاص فمش مؤثر، وفحص الصحة هيتحوّل أصفر/أحمر لو النسخ وقف لأي سبب.
- **تدوير المفاتيح:** لتغيير مفتاح R2 أو B2، اعمل توكن جديد ثم حدّث السر في GitHub، وشغّل `backup` يدويًا للتأكد.
