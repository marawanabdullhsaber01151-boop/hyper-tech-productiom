# تقرير المرحلة 03 — Foundation / النصف الأول

## نطاق هذا التسليم

هذا النصف يغلق طبقة reconciliation الآمنة قبل أي تشغيل على بيانات حقيقية. لا
ينفذ migration أو backfill تلقائيًا من داخل الحزمة، ولا يعتبر وجود كود متطابق
دليلًا كافيًا لتحويل كل السجلات بدون تقرير.

## ما تم تنفيذه

- إضافة `scripts/foundation-reconciliation-audit.mjs`.
- وضع التشغيل الافتراضي `report-only`.
- فحص وجود جداول Foundation وعمود الربط قبل تنفيذ أي استعلامات تشخيصية.
- تقرير كامل لعدادات:
  - أرصدة مخزون بلا تعريف Foundation.
  - مراجع Foundation مفقودة.
  - اختلاف كود المخزون عن الكود canonical.
- عينات bounded للمشاكل حتى لا يتحول التدقيق إلى استعلام ضخم أو استجابة غير
  محدودة.
- فحص تحويلات الوحدات غير الصالحة.
- فحص شجرة المواقع لاكتشاف الأب المفقود والدورات.
- فحص مراكز العمل المرتبطة بمواقع مفقودة.
- فحص الماكينات المرتبطة بمراكز عمل مفقودة.
- إضافة `--apply` اختياري لا ينفذ إلا exact-code backfill للروابط الفارغة:
  لا يستبدل رابطًا قائمًا ولا يحذف أو ينشئ تعريفات Foundation.
- إضافة pure reconciliation library واختبارات مستقلة للحالات الحرجة.

## طريقة التشغيل

```bash
npm run db:preflight
npm run db:migrate
npm run audit:foundation
```

سيكتب التقرير في:

```text
docs/reports/phase-03-foundation-reconciliation.json
```

بعد مراجعة التقرير وأخذ backup فقط:

```bash
npm run audit:foundation -- --apply
```

## ما لم يتم إثباته

لم يتم تشغيل audit أو migration على PostgreSQL فعلية لأن `DATABASE_URL` غير
موجودة في بيئة التسليم. لذلك لا توجد أرقام فعلية لعدد السجلات غير المرتبطة أو
المتعارضة داخل هذا التقرير.

## حدود النصف الثاني

النصف الثاني سيغلق واجهة reconciliation/التنبيهات التشغيلية، ويضيف فحوص
الصلاحيات وpagination/filters اللازمة للمراجعة اليومية، ثم يعيد تشغيل كل
التحققات ويُسلّم delta مستقلًا.
