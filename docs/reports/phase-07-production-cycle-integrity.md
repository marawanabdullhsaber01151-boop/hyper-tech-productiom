# تقرير تدقيق دورة الإنتاج — المرحلة 07

## القرارات المعتمدة

- **التنقل:** شاشات `factory-*` و`production-control.html` هي واجهات تشغيلية مرتبطة بالتنقل الديناميكي حسب الدور، وتظل `production.html` شاشة الملخص والرؤية الشاملة. رئيس مجلس الإدارة يرى كل هذه الشاشات لأن دوره موجود في مصفوفة التنقل.
- **تكرار الواجهات:** أُضيف عقد JavaScript مشترك للحالات ومراحل الإنتاج، وتستورد منه الواجهات بدل إعادة تعريف قائمة الحالات في كل شاشة.
- **طلبات الإنتاج:** تظل `production-requests` طبقة طلب وموافقة منفصلة في هذه المرحلة. التحويل التلقائي لم يُنفَّذ لأن الطلب الحالي لا يفرض وصفة تصنيع وعميلًا وكمية نهائية مرتبطة بشكل غير ملتبس؛ تحويله تلقائيًا الآن قد ينشئ أمرًا خاطئًا في مصنع كبير. يلزم قرار بيانات مستقل قبل ربطه بالمصدر الأساسي.

## نتائج التدقيق

| المجال | النتيجة |
|---|---|
| التنقل | الروابط التشغيلية كانت موجودة أصلًا داخل `src/lib/departments.ts`؛ لم يتكرر إنشاء روابط ثابتة في `index.html`، لأن `JS/nav-loader.js` هو النمط المعتمد ويعرضها حسب الدور. |
| الذرية | اعتماد المواد، تأكيد التسليم، والإلغاء داخل معاملات قاعدة البيانات. تم تقوية الانتقالات بقفل صف الأمر وتحقق الحالة داخل المعاملة. |
| التزامن | أضيف قفل `FOR UPDATE` وشروط حالة في تحديثات الانتقال لمنع النقر المزدوج أو جلستين من تطبيق الأثر مرتين. مفتاح تحويل المخزن أصبح حتميًا بدل الاعتماد على الوقت. |
| التدقيق | أضيف تسجيل انتقالات دورة الإنتاج داخل نفس المعاملة باستخدام `writeAuditEvent` وسجل `audit_events` القائم، مع الإبقاء على سجل التدقيق العام كشبكة أمان. |
| الصلاحيات | نقاط الإنشاء والاستلام والإرسال والمراحل والجودة والتسليم محمية بـ `requireRole`، واعتماد المواد والإلغاء بـ `requirePermission`، وتعديل موعد التسليم يتحقق من مالك الطلب على الخادم. |
| الحالات غير الصحيحة | أصبحت حالات الانتقال غير المسموح بها في دورة الإنتاج ترجع `409` بدل `400`، بما يتوافق مع حارس `assertProductionTransition`. |
| الحقول النصية | `modal-unit` تُرك نصًا حرًا لأن المشروع لا يملك جدول وحدات إنتاج معتمدًا؛ الوحدات تختلف حسب المنتج والوصفة. اسم العميل وتفاصيل الطلب وملاحظاته نصوص حرة صحيحة. المنتج والأولوية قوائم مرتبطة بمصدر وصفات/مجموعة حالات مغلقة. |
| الهجرة | `0047_production_workflow_hardening.sql` إضافية وقابلة لإعادة التشغيل، ويكتشفها `npm run db:migrate` تلقائيًا. لم أزعم تطبيقها على قاعدة حية لأن بيانات اتصال قاعدة المستخدم غير مرفقة. |

- `npm test` — **23 ملفًا، 137 اختبارًا ناجحًا، 3 متخطاة**.
