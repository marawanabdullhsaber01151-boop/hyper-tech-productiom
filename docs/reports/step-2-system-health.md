# Step 2 — صفحة «صحة النظام»

**المكان:** `/v2/staff/system-health` (الإدارة العليا: رئيس المجلس + المدير التنفيذي). **الـAPI:** `GET /api/v1/admin/system-health`.

## اللي اتغيّر
- **٢١ فحص حقيقي** في ٧ مجموعات (الأساس، الأمان، الصلاحيات، المبيعات، العملاء والبوابة، المخزون، الأخطاء). كل نتيجة: سليم / ملاحظة / مشكلة / ماتفحصش، بجملة عربية بسيطة + «اعمل إيه» + أمثلة + زر فتح الصفحة المعنية.
- **الفحص الفاشل بيظهر كمشكلة:** كل فحص مستقل وليه مهلة ٨ ثواني؛ لو فشل أو علّق بيظهر «ماتفحصش» بدل ما يختفي.
- **سجل الأخطاء:** هجرة `0079_app_error_events.sql` + `lib/errorEvents.ts`. أي خطأ 500 بيتسجل (المرجع `ERR-…` + المسار مع توحيد الأرقام + الرسالة، بدون stack ولا بيانات)، احتفاظ ٣٠ يوم.
- **كاشف جذر «فشل تحميل البيانات»:** فحوصات «موظف بدور غير معروف»، «دور من غير صفحات»، «صفحة مربوطة بدور اسمه غلط».
- **فحص المبيعات:** إجمالي الفاتورة ≠ مجموع الأصناف، **وفواتير أونلاين/أوفلاين المتلخبطة** (تمهيد لتنظيم المبيعات).
- تحديث تلقائي كل ٥ دقايق (بيقف لما التاب يتخبّى) + زر «افحص تاني».
- **اتشالت** `public/admin-health.html` (فحوصاتها كلها اتنقلت: الاتصال، الهجرات، الإعدادات، ملاحظات جودة البيانات) وصفحتها اتبدّلت في القايمة.
- مفتاح جديد `ACCESS.systemHealthRead` في سجل الوصول + اختبار بيطابق القايمة والـAPI وحارس الواجهة.

## حدود معروفة (بصراحة)
- مفيش فحص «آخر نسخة احتياطية»: النظام ما بيسجّلش نسخ؛ النسخ على Neon (Point-in-time). مقترح: يتضاف لما نفعّل تسجيل النسخ.
- فحص سلسلة التدقيق بيقف عند ١٠٠ ألف سجل ويكتب إنه «جزئي».
- `/admin/health` و`/admin/audit/findings` القدام فاضلين للتوافق مع أي مستهلك.
