# تقرير الخطة 06 — طلبات الانضمام (مكتب المراجعة)

## اللي اتعمل
**الباك**
- هجرة `0074_portal_applications_v2.sql` (إضافة فقط): مرحلة الطلب `stage` (new / needs_info / ready / approved / rejected / duplicate_auto_closed) متزامنة دايمًا مع عمود `status` القديم، مراجع مسؤول، نسبة اكتمال البيانات، ملاحظات داخلية، قرار الموافقة والشركة الناتجة، وقت رد العميل، وجدول `portal_application_events` (سجل أحداث لكل طلب).
- `src/lib/applicationMatching.ts`: توحيد الأسماء العربي (تشكيل، ألف/همزة، تاء مربوطة، «شركة/مؤسسة…»)، تشابه الأسماء (Levenshtein + كلمات مشتركة)، مطابقة بالموبايل/الإيميل الموحّدين، درجة ثقة وأسبابها، نسبة الاكتمال، حالة التأخير (SLA).
- راوتر جديد `/portal-admin/applications`: قايمة (بحث، مرحلة، مراجع، تأخير، تشابه، ترقيم، عدّادات)، CSV، meta، تفاصيل (مطابقات + سجل)، تعديل/تعيين مراجع/ملاحظات، طلب معلومات، رفض، موافقة.
- الموافقة بـ3 قرارات في transaction واحدة مع قفل الصف (مفيش موافقة مزدوجة): شركة جديدة، موظف في شركة موجودة (كلمة سر مؤقتة + رابط واتساب)، ربط بعميل قديم (جهة اتصال غير مربوطة). إعدادات الشركة (أقصى موظفين، طريقة الانضمام، المحادثة، الدور الافتراضي، مسؤول المبيعات، التصنيف، أقل كمية) بتتسجّل كإعدادات على مستوى الشركة بس لو مختلفة عن الافتراضي.
- جهة العميل: `POST /portal/applications` بقى بيرد 202 + رقم متابعة دايمًا؛ الرقم المكرر (له حساب أو طلب مفتوح) بيتسجّل `duplicate_auto_closed` ويظهر للعميل «تحت المراجعة». التتبع بيرجّع المرحلة ورسالة المراجع، و`PATCH /portal/applications/:ref` (برقم الطلب + الموبايل) بيخلّي العميل يكمّل المعلومات فيتحوّل الطلب لـ ready.
- الراوتات القديمة (`/portal-applications*`) لسه شغّالة وبتحدّث المرحلة والسجل.
- إعدادات جديدة: مهلة التنبيه (24 ساعة) والتأخير (48)، وقوالب أسباب الرفض ورسائل طلب المعلومات (نوع «قائمة نصوص» جديد في شاشة الإعدادات).

**الواجهة** `/v2/admin/portal-applications`: شرائح المراحل بعدّاداتها، عرض قايمة أو أعمدة (بيتحفظ الاختيار)، فلاتر وبحث، كروت على الموبايل، درج تفاصيل (بيانات + تعديل، التشابه بجنب الطلب مع زر «ضمّه/اربطه»، مراجع، ملاحظات داخلية، سجل)، معالج موافقة 3 خطوات (القرار ← إعدادات الشركة مع «الافتراضي: …» ← تأكيد) وبعده رابط التفعيل/كلمة السر. صفحة المتابعة عند العميل بقت تعرض نموذج لتكملة المعلومات.

## اختبارات
- وحدة: 11 اختبار للمطابقة والاكتمال والـSLA. ويب: 78. e2e: 12 اختبار جديد (3 قرارات، تكرار، موافقتين في نفس اللحظة، حلقة المعلومات، رفض، تعديل/CSV) + تعديل الاختبارات القديمة على ردّ 202.
- مراجعة بصرية على 1280 / 390 / 360 بدون سكرول أفقي أو أخطاء.

## اللي اتأجّل (وليه)
- المرفقات (صورة السجل التجاري): محتاجة جدول ملفات ورفع بفحص النوع، هتتعمل مع خطة الملفات.
- السحب والإفلات في الأعمدة: بدله زر «افتح الطلب» (أبسط وأأمن على الموبايل).
- pg_trgm مش متثبتة على القاعدة، فالتشابه بيتحسب في الكود (كافي للأحجام الحالية).
- تنبيه المراجعين تلقائيًا وجدولة SLA: محتاجين مهام مجدولة (خطة لاحقة)؛ الحالة بتتحسب وقت العرض.
- مفتاح قنوات الإرسال على مستوى الشركة: مفيش إعداد بالشكل ده لسه.
