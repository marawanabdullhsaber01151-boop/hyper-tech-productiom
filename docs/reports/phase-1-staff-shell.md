## ٢) اللي اتبنى

**واجهة جديدة (`web/src/staff/`):**
- `Login.tsx` — `/v2/login`: اسم مستخدم + كلمة سر ← (لو مفعّل 2FA) خانة الرمز. الحالات الست: عادي / تحميل / بيانات غلط / قفل بعدّاد `mm:ss` / رمز التحقق / انقطاع شبكة. بيحفظ الجلسة بنفس مفتاح وشكل الصفحات القديمة (`hyper_erp_session` = `{token,user,isNewDevice}`) فكل صفحة قديمة تفضل شغّالة. `?next=` بيتحقق منه (بيرفض أي رابط خارجي).
- `StaffShell.tsx` + `Sidebar.tsx` + `Header.tsx` — سايدبار ٢٦٠px (مطوي ٧٢px، والاختيار محفوظ)، تحت ٩٠٠px بيبقى drawer (Esc وscrim بيقفلوه). بيتبني من `GET /nav`: قسم ← محور ← صفحة، والصفحة الحالية `aria-current`، وروابط `/v2/...` تنقل داخلي، و`.html` القديمة تحميل كامل. الهيدر: اسم الصفحة، الاسم والدور، المظهر (فاتح/داكن/الجهاز)، خروج.
- `Home.tsx` — قسم واحد ← تحويل مباشر، غير كده شبكة أقسام. `SystemPages.tsx` — 404 / ممنوع / صيانة (الخطأ العام = `ErrorBoundary` الموجود).
- `nav.ts` (تحويل أيقونات FontAwesome ← Lucide، غير المعروف ← دايرة)، `prefs.ts`، `copy/staff.ts` (كل النصوص).

**السيرفر:** `GET /nav` بقى يرجّع `user:{name,role,roleLabel}` (`lib/roleLabels.ts` — اسم عربي لكل دور من الـ١٨ مع اختبار بيفشل لو دور جديد من غير اسم). ورد القفل (423) بقى فيه `details.retryAfterSeconds` عشان العدّاد.

**القديم:** `public/login.html` اتحذف. `public/JS/auth.js`: أي جلسة ناقصة/منتهية ← `/v2/login?next=<الصفحة>` (ومعالجة الدخول القديمة اتشالت منه). `scripts/repository-self-check.mjs` ما بقاش يشترط `login.html`.

## ٣) تصحيحات للمواصفة (اللي اتنفّذ غير المكتوب)
1. **التحقق الثنائي:** المواصفة بتقول `POST /auth/totp`، والمسار الحقيقي `POST /auth/login/verify-totp` بـ`{preAuthToken, code}`.
2. **صفحة الدخول القديمة** فعلًا `login.html` لكن `STAFF_LOGIN_URL` في الويب كان `/index.html` (صفحة اختيار الأقسام). اتحوّل لـ`/v2/login`. وبقيت `index.html` (اختيار الأقسام القديم) موجودة لحد المرحلة ٣.
3. **العدّاد:** السيرفر كان بيرجّع الدقايق في نص الرسالة بس. اتضاف `retryAfterSeconds`.
4. **أمر القبول `grep -rn "login.html"`** بيطلّع `portal-login.html` (صفحة تانية ومش مقصودة). الاختبار بيستخدم نمط `(^|[^-A-Za-z])login\.html`.
5. **أيقونات القائمة:** السيرفر بيبعت `landmark` / `cart-shopping`… من غير `fa-`؛ الجدول بيقبل الشكلين.

## ٤) لاحظت أثناء التنفيذ
- **دورين مالهمش أي قسم:** `purchasing_manager` و`buyer` (وحدة المشتريات اتحذفت في هجرة 0049). هيدخلوا ويشوفوا «مفيش أقسام متاحة لدورك». موثّق في اختبار (`departments.nav.test.ts`) كحالة معروفة.
- **أمان:** خطوة رمز التحقق الثنائي محمية بـ rate-limit على الـIP بس، ومفيش عدّاد محاولات فاشلة على مستوى الحساب (عكس كلمة السر). بعد إصلاح `trust proxy` الـIP-limit بقى فعّال، لكن **عدّاد لكل حساب** يستاهل تتم إضافته (KNOWN_ISSUES #14).
- صفحة «المبيعات» متسجّلة عمدًا تحت محورين (أونلاين وأوفلاين) بنفس الـid.

## ٥) ما اتعملش (عن قصد، مؤجّل للمراحل بعدها)
البحث السريع والجرس (أزرار معطّلة بنص «قريب» — المرحلة ٤)، تحويل الصفحات القديمة (`*.html`) للويب الجديد (المرحلة ٣)، لقطات الشاشة.

## ٦) خطوات التحقق (١٠ دقايق)
1. `npm run check:all` — لازم أخضر (ولو أي اختبار ويب فشل ابعتهولي).
2. افتح `/v2/login` ← ادخل بحساب عادي ← تظهر الرئيسية بالأقسام.
3. افتح صفحة قديمة (مثلًا `/sales.html`) من نافذة خاصة ← تحوّلك لـ`/v2/login?next=%2Fsales.html` وبعد الدخول ترجع لنفس الصفحة.
4. جرّب حساب مفعّل عليه 2FA (رمز غلط ← رسالة وتفضل، رمز صح ← تدخل).
5. جرّب ٥ محاولات غلط ← عدّاد القفل.
6. افتح `/v2/admin/xyz` ← صفحة «مش موجودة» جوّه الغلاف. وصغّر الشاشة لـ٣٩٠px ← الزر ☰ بيفتح القائمة.
7. ادخل بكل دور من الـ١٨ وقارن السايدبار بـ`/api/v1/nav`.
