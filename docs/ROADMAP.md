## ١) القواعد الحاكمة (بتتطبّق على كل خطوة)
- **E1–E10:** فلوس بالقروش كأعداد صحيحة، لا حذف فعلي لمستند مالي أو مخزني (عكس بقيد)، معاملة واحدة لكل عملية، هجرة مرقّمة بنسخة احتياطية قبلها، تحقق بمخطط مشترك، صلاحية لكل إجراء في السيرفر، اختبارات إلزامية للمال والمخزون والقيود، يشتغل بدون إنترنت، سجل نشاط بسلسلة hash، عربي RTL والنصوص في ملف الترجمة.
- **R1–R9:** أقصى أتمتة وأقل كتابة، سهولة واختصارات، تفاصيل «ليه؟» وشاشة تتبّع، ADR للقرار الكبير، أمان البيانات أولًا، قائمة اقتراحات مرقّمة بعد كل خطوة، تصميم قبل الكود، تطوير الفواتير والمالية بالكامل.
- **واجهة واحدة:** الصفحة القديمة تتحذف في نفس الخطوة اللي اتنقلت فيها، وتتظبط الصلاحيات في نفس الخطوة.

## ٣) لماذا الترتيب ده (منطق المهندس)
1. **حماية البيانات قبل التوسّع:** بيانات حقيقية على النظام، وكل موجة بعد كده بتضيف بيانات. النسخة الاحتياطية المُجرَّبة تسبق المالية.
2. **منصة الأنماط (outbox / saga / مهام بشرية) قبل الحوكمة والطلبات:** الاعتمادات والتصعيد والإشعارات والشكاوى والمرتجعات كلها بتعتمد على «مهمة بموعد وتصعيد» وإرسال مضمون. نبنيها مرة ونستخدمها في كل حتة.
3. **ترحيل صفحات الهندسة والبيانات الأساسية قبل المالية والسعة:** الأصناف والمواقع والمسارات والورديات هي مادة الخام للتكلفة والسعة.
4. **الحوكمة قبل التجاري والمالية:** عروض الأسعار وحدود الائتمان وإعادة فتح فترة مغلقة كلها محتاجة اعتماد بمستويات.
5. **المالية بالترتيب:** دفتر الأستاذ ← قيود تلقائية ← مدفوعات ← كشوف ← ائتمان وأرصدة ← تكلفة ← إقفال ← فاتورة داخلية. ما بعد التسليم (مرتجعات) بيحتاج قيد عكسي، فبييجي بعدها.
6. **العمل دون اتصال في الآخر:** محتاج API مستقر ومفاتيح تكرار (idempotency) على كل عملية كتابة.

## ٦) تصحيحات إلزامية على مواصفات الخطة الأصلية
(مأخوذة من الملحق، ومضاف عليها قرارات هندسية.)
- **الهجرات تبدأ من `0084`** (آخر هجرة موجودة `0083`). أرقام `0079`–`0086` في ملفات المراحل قديمة.
- **الفلوس بالقروش كأعداد صحيحة (E1):** مواصفات المحاسبة والفاتورة بتستخدم `numeric(14,2)`. بنستبدلها بـ`bigint` بالقروش، وتحويل العرض في طبقة واحدة.
- **ممنوع إنشاء جداول مكررة:** `approval_requests` موجود (نعدّل عليه)، السجل = `audit_events` (بدل `activity_log`)، الشركة = `portal_customers`، المنتج = `bom_recipes`، الإعدادات = `system_settings` + `portal_settings`، السعة = `foundation_*` + `engineering_routings` + `planning_capacity_loads` (بدل `plants/resources/routings` الجديدة).
- **الجرد قبل الإنشاء:** أي جدول جديد يتراجع على جرد الجداول (B2) قبل `CREATE`.

## ٧) تعريف «تمّت الخطوة» (DoD)
1. تصميم مكتوب قبل الكود، وADR للقرار الكبير (R4، R7).
2. قواعد نقية بدون قاعدة بيانات وبـاختبارات، وإلزامي للمال والمخزون والقيود (E7).
3. الصلاحيات متظبطة في السيرفر، واختبار بيقارن أدوار الواجهة بحراس المسارات (E6).
4. الصفحة القديمة اتحذفت، وروابطها بتحوّل، وكل قايمة بتشاور على الجديد.
5. النصوص في ملف الترجمة بعربي سليم (E10).
6. `npm run check:all` أخضر عندك. وأي فحص ما اتجرّبش عندي بيتقال صراحة.
7. حزمة بأوامر PowerShell، وقايمة «اقتراحات» مرقّمة (R6).
